安装步骤

四步，装进抖音网页。

01

启动本地 Fastify 服务

在 server/ 运行 npm.cmd install，把 .env.local.example 复制成 .env.local，填模型 Key 和 APP_TOKEN，再运行 npm.cmd run dev。看到 127.0.0.1:8787 就成功了。

02

下载并解压扩展

拿到扩展 zip 后解压到一个固定目录。不要放在下载临时目录里，Chrome 会在下次启动时找不到它。

03

加载已解压的扩展

地址栏输入 chrome://extensions（Edge 是 edge://extensions），开启「开发者模式」，点「加载已解压的扩展程序」，选择解压后的文件夹。

04

填服务地址和 APP_TOKEN

打开抖音网页，点悬浮球设置，填 http://127.0.0.1:8787 和 .env.local 里的 APP_TOKEN。点「测试连接」，看到服务状态正常再开始刷。

为什么还要本地服务？

不是没做一键版，是这版就是这个栈。

现有插件把模型 Key、prompt、语音过滤、SSE 都放在 Fastify 里；扩展只做页面。公开版如果改成浏览器直连模型，就要重写整条请求和配置链，和现有成果冲突。

取舍 这版优先保住已经验证过的插件行为：9 情绪、聊天、键盘隔离、历史记录、限时。代价是公开用户要跑一个本地服务。后续是否做“纯扩展 + 自带 API”是另一项架构决策，不在本次 UI 里偷偷改。

安装问题

常见卡点。

为什么 Chrome 提示“无法加载扩展”？
通常是没有选择解压后的文件夹，或者文件夹里缺少 manifest.json。重新解压，确认选择的目录里能直接看到 manifest.json，再加载一次。
装完后抖音页面没有悬浮球？
先在扩展管理页确认「上头了喵喵」是开启状态，然后刷新抖音页面。还要确认本地服务已经启动、设置里的服务地址和 APP_TOKEN 正确；没有令牌时插件不会主动开口。
测试连接一直失败？
先在浏览器打开 http://127.0.0.1:8787/health，确认服务在运行。再检查设置里的服务地址和 server/.env.local 的 APP_TOKEN 是否一致。模型 Key 只在服务端使用，不需要填进扩展。
能不能只装扩展，不跑服务？
当前版本不行。这是现有 Fastify 架构的限制，也是这次 UI 调整的重点：不再把页面写成“浏览器直连模型”的样子，避免用户装完发现对不上。
会不会影响抖音账号？
插件只读当前视频的公开信息和页面文案，不点赞、不评论、不关注、不刷数据。它不绕过登录、不自动操作账号。仍建议遵守抖音的用户协议。
